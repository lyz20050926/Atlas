# Five-minute demo script

This follows the training structure `hook -> problem -> solution -> demo -> impact -> close` while
keeping the actual agent decision cycle visible.

Start with `python launch.py` for the labelled local demonstration. Record open-ended model answers
and live catalogue operations only after explicitly launching `python launch.py --mode live` with
your own authorised configuration. Default demo responses are not live AI evidence. Use the final
source's validation report; any older live report remains dated historical evidence.

- **0:00–0:30 — Hook.** “A reading list is easy. A trustworthy plan that checks every book, fits your time and changes with your progress is not.” Show the completed Atlas journey for one second, then reset to the learner's goal.
- **0:30–1:00 — Problem.** An EEE student wants to enter embodied intelligence. Generic chat answers may recommend unverifiable or poorly matched titles, hide their reasoning and remain static when the learner gets stuck or loses time.
- **1:00–1:30 — Solution.** Introduce Atlas as an evidence-grounded reading agent. In one diagram show: define three complementary knowledge needs, retrieve from two catalogues, verify identity, score fit, build a constrained path, then observe progress and adapt only with learner approval.
- **1:30–2:05 — Goal and bounded planning.** Enter Python/ML/control background, six weeks, four hours weekly and Robotics/Cognitive Science/Ethics. Expand the trace so judges see the programmed `plan -> retrieve -> verify -> select -> check` workflow and its capped fallback branch rather than only its final answer. Do not describe it as open-ended autonomous reflection.
- **2:05–2:35 — Evidence and route.** Show the real cover, ISBN/source links, six shared fit dimensions, reservations and the time-bounded three-stage route. Open a poor search result briefly to prove that an unrelated biography is rejected rather than rationalized into the path.
- **2:35–3:10 — Learner feedback.** Tell Atlas “I am 40% through but sensor fusion is unclear.” Show saved progress, the grounded next action and persistent conversation. Ask to replace only the current book and confirm that the other stages and previous version remain intact.
- **3:10–3:30 — Progression.** Mark the current book 100% complete and show automatic advancement. Return to the completed stage using the stage selector to demonstrate that viewing history does not change the active stage.
- **3:30–4:15 — Impact and proof.** Show the free preflight report, 12-case deterministic scorecard and the separately labelled bilingual live report. Call out first-attempt schema validity, retrieval-tool success, end-to-end completion, token volume and loop cap. State that blind human fidelity review is pending.
- **4:15–5:00 — Close.** Show excerpt-grounded tutoring, then reduce weekly time and display the versioned revision. Close with: “Atlas does not just answer what to read; it verifies, explains, follows through and adapts with the learner.” Name the honest boundaries: no full-book access, local demo persistence and no claim of human-validated learning gain yet.

Record a cached fallback path before the final take. A source outage should demonstrate resilience, not
consume the five-minute video.
