# Ten-slide hackathon deck outline

1. **Mission.** NexMind Atlas: a trustworthy, adaptive reading agent for learners entering a new field.
2. **Problem.** Generic reading lists are hard to verify, poorly personalized and static after the learner starts. Use one learner story; do not invent market statistics.
3. **Solution.** Show the complete learner journey and the difference from a one-shot chatbot.
4. **Agent method.** Visualize `plan -> retrieve -> verify -> select -> follow through -> adapt`, including the human approval boundary.
5. **Technical architecture.** Streamlit, typed LangGraph state, catalogue tools/cache, Bedrock structured output, SQLite and evaluation pipeline.
6. **Originality.** Knowledge-first role planning, field-level provenance, transparent fit, stage-scoped replacement and a persistent learning loop in one product.
7. **Benefits.** Demonstrate traceability, bounded execution, preserved progress and bilingual independence. Separate demonstrated product behavior from learning outcomes that still need a pilot.
8. **Demo.** Use six screenshots: goal, agent trace, verified recommendation, mentor feedback, automatic stage advance and version comparison.
9. **Evidence and roadmap.** Topic 4 six-metric scorecard, the final source's actual preflight result, dated historical live smoke result, blind-review plan, hosting/auth/security roadmap. Do not present default demo mode as live model evidence.
10. **Close.** “Atlas verifies what to read, helps you understand it and adapts with you.” Ask judges to inspect the working prototype and machine-readable reports.

Keep one message per slide. Every numeric claim should point to a generated report, test output or
clearly identified pilot result.
